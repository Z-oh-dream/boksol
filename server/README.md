# boksol 信令与对战中继

服务端按联机码建立房间，确认作品与 ROM 哈希一致后广播昵称名单。《续・我们的太阳》和《我们的太阳 DS》可选择 2、3 或 4 人，《新・我们的太阳》为 2 人。原作游戏在客户端的模拟器中运行，服务端通过 WebSocket 转发准备消息、GBA 有序字节流和 DS 数据报。房间与连接状态保存在内存中。

## 本地运行

安装 .NET 10 SDK。在本目录运行以下命令。

```sh
dotnet run --project Boksol.Server.csproj -c Release -- --urls http://127.0.0.1:8787
```

浏览器访问 `http://127.0.0.1:8787/healthz` 可检查服务是否启动。所有玩家在 boksol 的「信令服务器地址」填入 `ws://127.0.0.1:8787` 后，选择同一 ROM 版本并使用相同联机码。程序会自动补上 `/v1/room`，也可以填写包含路径的完整地址。测试局域网其他设备时，将监听地址改为本机局域网 IP，并在客户端使用该 IP。

## 公网运行

```sh
dotnet publish Boksol.Server.csproj -c Release -o publish
dotnet publish/Boksol.Server.dll --urls http://127.0.0.1:8787
```

在服务器上用支持 WebSocket 的 HTTPS 反向代理公开 `/v1/room`，将连接转给本机的 8787 端口。配置 TLS 证书，并让所有玩家填写同一个 `wss://` 地址。同一房间的连接需到达同一个服务端进程。代理应允许长期 WebSocket 连接。

房主先点击开始配对，并按预设人数等候玩家，满员后启动游戏。配对等待窗口为两分钟。连接质量取决于玩家到服务端的延迟和带宽。局域网观战和地址留空时的双人发现保留。也可以在局域网部署服务端，让三到四名玩家连接同一地址。

Windows 本机中继已验证《续・我们的太阳》三人与四人进入原作对战、《新・我们的太阳》双人进入摩托车设置，以及《我们的太阳 DS》双人进入由房主操作的原作规则页。DS 三至四人从各自存档启动。四席位配对和核心连接已通过，四开复测时第三席在尝试加入原作无线房间后断开。

## 协议 v2

1. 玩家连接 WebSocket 路径 `/v1/room` 后发送 `BOKSOL2|<联机码>|<作品 ID>|<ROM SHA-256>|<人数>|<昵称>`。作品 ID 为 `boktai2`、`boktai3` 或 `boktaids`，哈希使用 64 位小写十六进制。昵称最多 16 个 UTF-16 代码单元，使用 UTF-8 Base64 编码，允许为空。
2. 等待时服务端用 `ROOM|<容量>|<昵称1>|<昵称2>|...` 更新名单。满员后发出 `OK|<席位>`，席位从 1 开始。遇到问题时返回 `ERROR|GAME`、`ERROR|ROM`、`ERROR|FULL`、`ERROR|BUSY`、`ERROR|TIMEOUT` 或 `ERROR|PROTOCOL`。
3. 客户端发送的文本是房间同步消息，服务端加上 `<来源席位>|` 后广播给其他玩家。二进制消息第一字节为目的席位，服务端将其换成来源席位。游戏二进制流量走房主与来宾之间的连接。服务端保留消息边界和每个玩家发送消息的顺序。
4. 等待期间退出会释放席位。游戏开始后任一玩家断开会结束本次配对，可以继续使用联机码建房。
